# Implementation decisions

- The project mirror contained an unrelated application and no licensed news export. Sourcera has a separate project directory and synthetic fixture with reserved example-domain source URLs. Stored normalized text is available inside the product for inspection.
- Demo sessions instantiate one of two stable preference templates with a new, private identity at each sign-in. Registered accounts persist across logins. Only registered operators can import or correct clusters. Demo listeners can read aggregate costs.
- Every worker uses the same Python package with an independent queue and process. The split targets the operationally distinct stages and avoids duplicating data models.
- The no-key path uses the deterministic multilingual lexical embedding adapter, extractive model and offline eSpeak NG speech. The semantic model, remote structured model, ElevenLabs and Whisper-compatible adapters are individually selectable. Runtime downloads and external transfers require operator configuration.
- Narration uses only evidence available in its requested language. Number or date changes, altered attribution and unsupported translations fail the gate. Target duration limits selection, and a short evidence set can yield a substantially shorter edition.
- Seed fixture publication times are relative to the initial import. Absolute timestamps in authorized data stay intact. Existing demo imports keep their dates after restart. For historical periods the user can choose explicit story IDs.
- Source URLs and source excerpts are trusted only as provenance. Remote article text is treated as data, and generated words and claim IDs pass a separate deterministic validator. Human editorial review is still needed for ambiguous event identities and differently worded disagreements.
- WAV durations come from decoded sample counts. MinIO objects have content-derived keys. The gateway enforces listener ownership on every audio request. The team chose original synthetic voice styles and licensed provider voice IDs.
- Compose targets a loopback, single-host demonstration. A transient SQLite/local-storage profile supports environments without a container runtime. Runtime data is excluded from version control.

- The home page follows the supplied three-column sketch with circular speaker choices, a voice-settings rail, a daily/weekly edition panel and a discussion-settings rail. Speaker portraits are original CSS illustrations tied to existing synthetic delivery styles.
- Discussion preferences select source search or the server-configured assistant. With the default local provider both choices use local intent rules. With an API or Ollama provider the configured option can classify less obvious requests with that model. The evidence gate applies to both. The UI displays the actual configured model name. This preference is added by migration 0002_discussion_model with a default preserving existing behavior.

- The latest home-page revision uses a compact music-player layout. Its primary control starts the buffered daily recording. Three voice portraits and playable daily/weekly episode covers follow below. Language, duration, schedule, provider/model choice and other controls live on the Settings page. A chosen voice is applied through an explicit new-edition action. Prepared weekly episodes play from their cover, and missing weekly episodes are labeled as creation actions.
