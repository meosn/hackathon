# Проверяемый отчёт для жюри — 21 ноября 2026

Требования взяты из предоставленного одностраничного PDF «The Liquid Briefing» (MAIN AI Hackathon 2026): группировать события, объяснять важность и соответствие слушателю, связывать утверждения с источниками, показывать стоимость полного набора и оценку ×10. PDF является спецификацией продукта, а не тестовым ключом.

## Что изменено

- `editorial-v2`: важность и срочность рассчитываются раздельно по заголовку и первым 1 400 символам статьи. Учитываются безопасность людей, решения центробанков, макроданные, финансовые сбои, общественные события и корпоративные результаты. Есть английские, немецкие и нидерландские правила. Бонус независимых издателей ограничен 0,12; прогнозы, мнения и продвижение понижаются. API отдаёт базовые значения, сработавшие сигналы, вклады и ограничения. Это проверяемая эвристика, а не откалиброванная вероятность важности или истины.
- В карточке события раздел **Why this story matters** показывает основания и численные оценки. В **Make a briefing** у рекомендуемых событий видны причины персонального выбора. `/api/v1/recommendations` возвращает `selection`: значения факторов, веса, вклады, итоговый балл и явные перестановки для разнообразия, изученных интересов и критических событий. Порядок после таких перестановок может отличаться от сортировки по баллу.
- При объединении явно разные кварталы/годы в заголовках являются жёсткой границей даже для модели проверки. Разные суммы одного периода сохраняются вместе для проверки разногласий. Старые кластеры автоматически не разделяются: инвентаризация выдаёт кандидатов для ручного просмотра.
- Модуль `app.news.audit` без изменения базы проверяет точные смещения цитат, воспроизводимость оценок и несовместимые отчётные периоды внутри существующих кластеров. JSON содержит ID и производные сигналы, без полных статей. Синтетические записи явно помечены.

## Как воспроизвести

Из корня репозитория:

```bash
make test
./scripts/compose.sh exec -T api python -m app.news.editorial
./scripts/compose.sh exec -T api python -m app.news.audit > jury-audit.json
```

Первая команда запускает backend/frontend тесты и сборку интерфейса. Вторая показывает, сколько оценок изменится, без записи и вызовов модели. Чтобы применить новые оценки к существующим событиям: `./scripts/compose.sh exec -T api python -m app.news.editorial --apply`. После этого `counts.priority_drift` в отчёте должен быть нулевым при отсутствии параллельного обновления данных.

`invalid_evidence` и `period_conflicts` дают ID для проверки через существующие страницы источников и операторские merge/split API. Ненулевое значение требует проверки; нуль не означает полноту фактов или доказанную правильность всех кластеров. Аудит охватывает активные события, а не все записи/аудио за всю историю.

Откройте **Make a briefing** под двумя своими тестовыми аккаунтами с разными интересами и сравните события и объяснения. Такие аккаунты являются только внутренними сценариями. Они не заменяют четыре профиля организаторов и wildcard. Для трёх утверждений из подготовленного аудио откройте транскрипт, цитаты и оригинальные публикации; сравните число, единицу, дату и контекст. Проверка подготовленного сценария не распространяется автоматически на каждую фразу realtime-разговора.

## Доказательства и незакрытые критерии

| Критерий PDF | Проверяемые материалы | Ограничение |
|---|---|---|
| Доверие, 25 | Цитаты/смещения, gate публикации, `invalid_evidence`, тесты verification | Совпадение с источником не доказывает истинность; внешняя проверка официальных релизов не выполнена |
| Соответствие слушателю, 20 | Настройки, факторы `selection`, два собственных сценария | Официальные четыре профиля и wildcard не предоставлены |
| Осмысление новостей, 20 | Сигналы приоритета, тесты кластеризации, `period_conflicts` | Официального ключа нет; precision/recall и качество сортировки по нему не измерены |
| Масштаб/стоимость, 15 | [Расчёт стоимости](COST_ANALYSIS.md), локальные правила без дополнительных LLM-вызовов | Оценка ×10 линейная; не измеренный нагрузочный тест и не счёт провайдера |
| Прослушивание, 10 | Подготовленные выпуски, транскрипт и ссылки | Темп и качество нужно оценивать прослушиванием; новая озвучка зависит от лимитов провайдера |
| Продукт, 10 | Персональные аккаунты, расписания, интерфейс источников | Готовая презентация и проверенная коммерческая модель не представлены |

В [аудите готовности](HACKATHON_READINESS.md) записаны ранее наблюдавшиеся показатели архива и в [расчёте стоимости](COST_ANALYSIS.md) — допущения. Они не являются новыми измерениями этого изменения. Для показа challenge-недели используйте лицензированный архив с его датой отсчёта; текущая лента live не заменяет обязательную демонстрацию на наборе организаторов. Лицензионные тексты и исходный PDF в Git не добавляются.
